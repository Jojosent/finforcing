# FinForcing AI — Интеллектуальная система выявления мошеннических банковских транзакций с использованием машинного обучения и Explainable AI (SHAP)

> **Конкурсный трек:** AI for Finance (Скоринг, антифрод и прогнозирование рисков)  
> **English:** Intelligent Fraudulent Banking Transaction Detection System Using Machine Learning and Explainable AI  
> **Стек:** Next.js 14 (App Router) • TypeScript • TailwindCSS • Firebase Firestore • LightGBM • Random Forest • XGBoost • Logistic Regression • TreeSHAP • Vercel Ready

---

## Цель и назначение проекта

Разработка и экспериментальная оценка веб-прототипа интеллектуальной системы, которая на основании параметров банковской транзакции (сумма, время, тип, характеристики клиента, получателя и история операций) автоматически:
1. Вычисляет точную вероятность мошеннической операции (**Fraud Probability**).
2. Присваивает стандартизированный риск-скор от 0 до 100 (**Fraud Risk Score**):
   - **0–30**: Low Risk (Операция безопасна, автоматическое проведение).
   - **31–70**: Medium Risk (Подозрительная операция, запрос 2FA / биометрии).
   - **71–100**: High Risk (Критический фрод, блокировка перевода и аудит).
3. Формирует объяснение на естественном языке с помощью методов **Explainable AI (TreeSHAP)** для сотрудников финансового мониторинга и комплаенс-контроля.
4. Предоставляет интерактивный симулятор P2P переводов между реальными зарегистрированными клиентами банка с поддержкой демонстрации на двух устройствах (Ноутбук + Смартфон) в режиме реального времени.

## Исследовательская задача конкурса

> **Вопрос исследования:**  
> *«Какой алгоритм машинного обучения обеспечивает наилучший баланс между обнаружением мошеннических транзакций и количеством ложных срабатываний, и может ли применение Explainable AI сделать решение модели интерпретируемым для специалиста финансового мониторинга?»*

### Результаты сравнительного эксперимента (Тестовая выборка N = 6 250):

| Модель машинного обучения | Recall (Fraud) | Precision (Fraud) | F1-Score | ROC-AUC | Ложные тревоги (FP) | Резюме |
| :--- | :---: | :---: | :---: | :---: | :---: | :--- |
| **Logistic Regression** | **99.44%** | 86.83% | 0.9271 | 1.0000 | 27 операций | Линейный базовый уровень, много ложных тревог |
| **Random Forest** | 98.88% | 95.16% | 0.9699 | 0.9999 | 9 операций | Надежный ансамбль деревьев |
| **LightGBM (Чемпион)** | 98.88% | **95.68%** | **0.9725** | **1.0000** | **8 операций** | **Наилучший баланс F1 и минимальный FP** |
| **XGBoost** | **99.44%** | 94.68% | 0.9700 | 0.9999 | 10 операций | Высочайшая чувствительность к редким аномалиям |

### Научные выводы:
1. **Выбор чемпиона:** Градиентный бустинг **LightGBM** обеспечивает наивысшую точность (**Precision 95.68%**) при сохранении высочайшего уровня обнаружения (**Recall 98.88%**). Число ошибочно заблокированных добросовестных клиентов снижено с 27 до **8 операций**, что критически важно для минимизации трения в клиентском банковском опыте.
2. **Роль Explainable AI:** Применение алгоритма **TreeSHAP** устраняет проблему «черного ящика». Система вычисляет точный вклад каждого признака ($\phi_i$) в итоговый скор, формируя прозрачный аудит-след, удовлетворяющий регуляторным требованиям Национального Банка и базельским стандартам комплаенса.

## В какое время отправка перевода наиболее подозрительна?

Анализ 25 000 банковских транзакций выявил критическую циркадную аномалию:

- **Самый опасный интервал:** **с 01:00 до 05:00 ночи** (критический пик: **02:00 — 02:59**).
- **Показатели риска в 02:00–02:59:**
  - Доля мошенничества среди ночных операций: **41.51%** (по сравнению с 1.1% днем).
  - Риск-множитель: **14.45x** выше дневного среднего уровня.
- **Причины ночной уязвимости:**
  1. *«Спящая жертва»:* Клиент спит и не реагирует на SMS/Push-уведомления о списаниях в течение 4–6 часов.
  2. *Credential Stuffing:* Хакерские скрипты по подбору паролей запускаются преимущественно в ночное время.
  3. *Дроп-обналичивание:* Срочный вывод похищенных средств на подставные карты до начала рабочего дня банка.

## Основные модули веб-приложения

- **Главная (Transaction Analyzer):** Интерактивный ввод параметров (сумма 850 000 ₸, время 02:43, новый получатель) $\to$ Мгновенный расчет: *Fraud Risk 92% — HIGH RISK* + SHAP факторы.
- **P2P Транзакции (Dual-Device Real-Time Mode):**
  - Поддержка реальной регистрации и авторизации клиентов в **Firebase Firestore**.
  - Отображение активных онлайн-пользователей с номерами счетов.
  - Режим сплит-скрина: **Ноутбук (рабочее место Отправителя)** слева и **Смартфон (мобильный банкинг Получателя)** справа.
  - При отправке средств мобильный интерфейс получателя в реальном времени отображает поступление или экран блокировки с перечислением факторов риска.
- **Временной анализ:** 24-часовой график с аналитикой киберпреступности.
- **Пакетный CSV Анализ:** Аудит 1000 транзакций в один клик. Сортировка по уровню риска, фильтры, SHAP-инспекция строк и экспорт отчета в CSV.
- **Бенчмарк моделей:** Сравнение 4 алгоритмов ML, матрица ошибок и глобальный рейтинг важности признаков по SHAP.

## Запуск и Развертывание

### 1. Локальный запуск

```bash
# Клонирование репозитория
git clone https://github.com/Jojosent/finforcing.git
cd RoadToAlmaty

# Установка зависимостей
npm install

# Запуск в режиме разработки
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000) в браузере.

### 2. Запуск Python пайплайна машинного обучения

```bash
# Генерация датасета (25 000 транзакций)
python ml_pipeline/prepare_dataset.py

# Обучение 4-х моделей, расчет метрик и SHAP
python ml_pipeline/train_and_evaluate.py
```

### 3. Деплой на Vercel

Проект полностью оптимизирован для мгновенного развертывания на **Vercel**:
1. Перейдите на [vercel.com](https://vercel.com) и импортируйте репозиторий `Jojosent/finforcing`.
2. В **Environment Variables** добавьте переменные Firebase (см. `.env.example`).
3. Нажмите **Deploy**! Инференс-движок работает в serverless-режиме с нулевой задержкой (<3ms).

## Интеграция с Firebase

В проекте настроена автоматическая загрузка Firebase Admin SDK (из любого локального файла `*firebase-adminsdk*.json` или переменной `FIREBASE_SERVICE_ACCOUNT`) для проекта `finforcing`:
- **Firebase Firestore:** Хранение зарегистрированных клиентов (`bank_users`), балансов и журнала транзакций (`bank_transactions`).
- **Синхронизация между устройствами:** Поддержка работы как с двух физических устройств (телефон + ноутбук), так и через встроенный сплит-скрин.
